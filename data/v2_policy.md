# v2 优化实验

依据 v1 失败结论，保持基础 revision、统一提示词、JSON 协议和答案/EOS loss 不变，从原始 Qwen3-4B 重新训练。
新数据独立编写，没有数字扩展；两种语言反向样本保持同组，同原文不同上下文也保持同组。旧数据仅取 v1 训练集每组一对，移除泛化的空泛上下文，不重放任何旧开发/测试内容。

逐条阅读 244 条 API 候选。四条对应作者填反的语言字段，保存原始记录并重新标注更正输入；有效候选 240 条中保留 214 条、修订 24 条、拒绝 2 条。修订只针对具体语义/自然表达问题，接受等义不同措辞。最终训练为 238 条新增 + 150 条旧训练，共 388 条、192 个来源组。
这是聚焦的优化实验，并未达到 3,000 个独立新语义样本。开发/测试各 40 条、20 对短句/短段落，范围有限。验收负责人是用户授权的 Codex。

方向回归检查另发现开发集第20对语言字段填反，正式运行使用 `dev_corrected.jsonl`，原文件与初始基线生成留作历史。两次中止的训练目录不参与权重选择：一次审核时间重写导致全记录指纹变化，一次开发方向检查失败。最终训练保存实际加载的 train/dev 快照，并与当前冻结文件核对一致。更正和中止记录不能隐去。

预先固定配置：NF4、BF16、rank16/alpha32、七类线性层、长度1024、batch1/累积16、学习率3e-5、dropout0.05、1epoch、每8步评估与保存。旧实验为学习率1e-4、dropout0、每个句式20个数字变体。
多个因素同时调整，比较只能说明这一整套配置的结果，不能单独证明学习率或数据是根因。

在查看新测试输出前，以新开发集最低 loss 选 checkpoint；检查开发集生成后冻结权重，独立测试仅做一次验收，不依据测试选权重或修订训练目标。
新基础模型与候选使用相同 CPU 隔离、量化、提示词及贪心解码。逐条语义判定与 JSON 判定独立。
推进为新的默认实验版本须同时满足：新测试 JSON 合法率至少95%；严重问题不多于基础模型；语义可接受条数不低于基础模型。只满足这些相对标准仍不代表可靠交付；正式语义通过要求该集合没有严重问题，且至少95%语义可接受。
若有关键漏译、否定/单位变化、无依据新增事实或语言方向失败，按严重问题记录；保留实验权重和证据，不粉饰验收结论。

原始数据指纹与配置在 `prepared/v2/split_manifest.json`；源字段更正在 `../runs/v2-source-corrections.json`；最终训练指纹与逐条动作在 `../runs/v2-data-acceptance.json` 和 `generated/v2_decisions.jsonl`。
